## 1. 背景与目标

作者需要一个自己能长期维护的个人站点，用来发布技术文章和日常感悟。读者可以浏览、搜索、按标签筛选，并用 GitHub 账号评论。

v1 成功标准：作者能独立完成「写草稿 → 发布 → 读者看到 → 读者评论 → 作者删评」的闭环；站点可用 Docker Compose 在本机或单机服务器上跑起来，不依赖 Nginx 和 Redis。

## 2. 用户与角色


| 角色  | 是谁          | 能做什么                                      |
| --- | ----------- | ----------------------------------------- |
| 读者  | 任何访问站点的人    | 浏览已发布文章、搜索、按标签筛选、查看关于我；评论前必须 GitHub 登录    |
| 作者  | 站点唯一管理员（本人） | 登录后台；写/改/删文章；草稿与发布；管理标签；编辑关于我；删除评论；上传文章配图 |


v1 只有一名作者。作者账号由环境变量配置，不提供注册。

## 3. 核心使用场景

1. **作者写技术文**：后台用 Markdown 写一篇带代码块的文章，先存草稿，改完后发布；首页立刻出现该文。
2. **作者写感悟**：发一篇带标签（如「随笔」）和配图的短文，读者从标签页进入。
3. **读者找旧文**：在搜索框输入关键词，命中标题或正文中的已发布文章。
4. **读者讨论**：打开一篇文章，用 GitHub 登录后发表评论，评论立即可见。
5. **作者维护讨论区**：看到不当评论后，在文章页或后台删除，该评论对所有人消失。

## 4. 信息架构

```
公开站
├── 首页 /                 已发布文章列表（分页）
├── 文章 /posts/:slug      正文 + 标签 + 评论
├── 标签 /tags             全部标签
├── 标签 /tags/:slug       该标签下的已发布文章
├── 搜索 /search?q=        搜索结果
└── 关于 /about            关于我

后台 /admin
├── /admin/login           作者登录
├── /admin/posts           全部文章（含草稿）
├── /admin/posts/new       新建
├── /admin/posts/:id/edit  编辑（Markdown、标签、发布状态、配图）
└── /admin/about           编辑关于我
```

未登录访问 `/admin/**`（除登录页）时跳转到登录页。

## 5. 功能需求

### 5.1 文章（作者）


| ID    | 需求                                         | 优先级 |
| ----- | ------------------------------------------ | --- |
| FR-01 | 作者可创建文章：标题、正文（Markdown）、可选摘要、可选封面图、零个或多个标签 | P0  |
| FR-02 | 文章状态为 `draft` 或 `published`。新建默认为草稿        | P0  |
| FR-03 | 作者可将草稿发布；发布后生成或确认 `slug`，记录 `published_at` | P0  |
| FR-04 | 作者可将已发布文章撤回为草稿；撤回后公开列表与详情不再展示              | P0  |
| FR-05 | 作者可编辑未删文章的标题、正文、摘要、封面、标签、slug（slug 冲突时拒绝）  | P0  |
| FR-06 | 作者可删除文章；删除后评论一并不可见（级联或等效）                  | P1  |
| FR-07 | 后台文章列表展示草稿与已发布，可按状态筛选                      | P0  |


### 5.2 文章（读者）


| ID    | 需求                                                 | 优先级 |
| ----- | -------------------------------------------------- | --- |
| FR-08 | 首页分页列出已发布文章：标题、摘要或正文截断、发布日期、标签；按 `published_at` 倒序 | P0  |
| FR-09 | 文章详情渲染 Markdown（GFM：标题、列表、链接、表格、代码块）               | P0  |
| FR-10 | 未发布或未知 slug 返回「文章不存在」，不泄露草稿标题                      | P0  |
| FR-11 | 代码块有语法高亮                                           | P1  |


### 5.3 标签


| ID    | 需求                                      | 优先级 |
| ----- | --------------------------------------- | --- |
| FR-12 | 标签有唯一 `name` 与 `slug`；写文章时可选用已有标签或创建新标签 | P0  |
| FR-13 | 公开标签页列出至少被一篇已发布文章使用的标签及文章数              | P0  |
| FR-14 | 按标签可查看该标签下已发布文章列表                       | P0  |


v1 不做独立的「分类」实体。分类用标签表达（例如「技术」「随笔」）。

### 5.4 搜索


| ID    | 需求                     | 优先级 |
| ----- | ---------------------- | --- |
| FR-15 | 读者可按关键词搜索已发布文章，匹配标题与正文 | P0  |
| FR-16 | 空关键词不发起无效全库扫描，提示输入关键词  | P1  |
| FR-17 | 无结果时展示明确空状态，而不是空白页     | P1  |


### 5.5 关于我


| ID    | 需求                                 | 优先级 |
| ----- | ---------------------------------- | --- |
| FR-18 | 公开 `/about` 展示作者用 Markdown 维护的单页内容 | P0  |
| FR-19 | 作者可在后台更新关于我；未写过时公开页展示空状态文案         | P0  |


### 5.6 评论与 GitHub 登录


| ID    | 需求                                        | 优先级 |
| ----- | ----------------------------------------- | --- |
| FR-20 | 未登录读者可看已有评论，不能提交                          | P0  |
| FR-21 | 「使用 GitHub 登录」走 GitHub OAuth；成功后回到原文      | P0  |
| FR-22 | 已登录读者可对已发布文章提交评论；提交后立刻对所有人可见              | P0  |
| FR-23 | 评论展示 GitHub 头像、login、正文、时间；正文纯文本，做 XSS 消毒 | P0  |
| FR-24 | 评论有长度上限（默认 2000 字）；空评论拒绝                  | P0  |
| FR-25 | 作者可删除任意评论；删除后立即不可见。v1 读者不能删自己的评论          | P0  |
| FR-26 | 读者可退出 GitHub 登录状态                         | P1  |


v1 不做评论审核、回复楼中楼、点赞。

### 5.7 作者登录与后台


| ID    | 需求                         | 优先级 |
| ----- | -------------------------- | --- |
| FR-27 | 作者用环境变量中的用户名、密码登录后台        | P0  |
| FR-28 | 错误凭据不得泄露「用户是否存在」；登录失败有通用提示 | P0  |
| FR-29 | 后台写操作（文章、关于我、删评、上传）必须带作者会话 | P0  |
| FR-30 | 作者可退出后台                    | P0  |


作者会话与读者 GitHub 会话分离。同浏览器可以同时是「已登录读者」和「未登录作者」，互不影响。

### 5.8 配图


| ID    | 需求                                 | 优先级 |
| ----- | ---------------------------------- | --- |
| FR-31 | 作者可上传图片，得到可插入 Markdown 的本地 URL     | P1  |
| FR-32 | 限制类型（jpeg/png/gif/webp）与大小（默认 5MB） | P1  |


### 5.9 部署与工程


| ID    | 需求                                                       | 优先级 |
| ----- | -------------------------------------------------------- | --- |
| FR-33 | 代码由 Git 管理，远程为 `showboat-dev/zw-blog`                    | P0  |
| FR-34 | `docker compose up` 可启动 `web` 与 `api`；SQLite 数据落在 volume | P0  |

## 6. 非功能需求


| ID     | 类型  | 要求                                              |
| ------ | --- | ----------------------------------------------- |
| NFR-01 | 安全  | 管理员密码与 GitHub `client_secret` 只存在环境变量，不入库、不进前端包 |
| NFR-02 | 安全  | 公开 API 不返回草稿；后台 API 未授权返回 401                   |
| NFR-03 | 安全  | 评论与 Markdown 渲染防 XSS；Markdown 允许的 HTML 白名单见技术文档 |
| NFR-04 | 性能  | 单机、个人访问量；列表默认每页 10 篇；搜索走 SQLite FTS5            |
| NFR-05 | 可用性 | 公开页桌面与手机可用；后台以桌面写作为主，手机能改字即可                    |
| NFR-06 | 可维护 | 公开文案为中文；接口错误有稳定错误码，见技术文档                        |
| NFR-07 | 可测试 | 每个 P0 需求都能写成自动化测试；关闭对应 GitHub Issue 前必须跑通       |


## 7. 约束与假设

- 技术栈锁定：**Vite + React** 前台、**FastAPI** 后台、**SQLite** 数据库。
- 作者会自行在 GitHub 创建一个 OAuth App，把 Client ID / Secret 配进环境变量。
- 部署环境能装 Docker；开发机有 Python 3.12+ 与 Node 20+。
- 第一版主要靠链接分享，不要求搜索引擎 SSR。

## 8. 明确不做（v1 Out of Scope）

- RSS、邮件订阅、newsletter
- Nginx、Redis、独立对象存储 / CDN
- 多作者、读者注册（非 GitHub）、评论审核队列
- 评论回复、点赞、通知
- 独立分类体系（与标签并存）
- 阅读量统计、第三方分析
- 深色模式（若实现也不作为 v1 验收项）
- PostgreSQL（仅当单库不够用时再迁，见架构文档）
